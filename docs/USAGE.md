# 乔巴便笺 使用指南

乔巴便笺（qiaoba-notes）是一个用 Claude Code 开发的桌面便笺工具，代码完全开源，大家可以直接下载使用，也可以基于自己的需求进行二次开发。

## 一、使用场景

开发这个工具的初衷，是因为在使用 Claude Code 时经常需要同时跑多个任务。

比如 A、B、C 三个窗口可能同时在跑 ComfyUI 工作流：A 窗口在调试提示词、B 窗口在优化工作流、C 窗口在跑其他任务；与此同时可能还有 D 窗口在改 bug，E 窗口在做排版任务。有些任务需要等很长时间（比如视频渲染），有些需要及时反馈（比如排版），每个任务可能都处于不同阶段——有的进行中，有的在等指令，有的已经搞定了。

大部分人的脑子都是"单线程"，不支持真正的多任务并发，这种场景下就需要一个工具来记录每个窗口的任务目标和工作进度，避免自己被绕晕。

乔巴便笺的核心功能，就是记录每一个任务的目标以及进度，通过**带层级、带状态标记的结构**，让每一条任务的进度和目标都清清楚楚地钉在眼前。简单说，这更像一个"任务进度追踪器"，只不过披了一层便笺的皮。

## 二、下载与安装

从 GitHub 的 Releases 页面下载安装包，双击 exe 安装程序，一路下一步装完即可。

装完之后，软件有两个层面的界面：

- **主列表窗口**：能看到所有便笺卡片、顶部有搜索框和"+新建"按钮的总览界面，是"任务面板"。
- **便笺窗口**：点开某一条便笺后弹出的黄色小窗口，是实际写字、记进度的地方。

## 三、主列表窗口：管理你所有的便笺

### 1. 新建便笺

- 主列表窗口顶部的"+新建"按钮。
- 任意一个已打开的便笺窗口，标题栏上也有一个"+"按钮——点击会直接新建并打开一个空白便笺，不用切回主列表。

这么设计是因为主列表窗口平时一般保持关闭状态。如果正在某个便笺里记录东西，突然想到另一个任务，可以不通过主列表，直接原地点"+"新建。

> 目前软件没有内置全局快捷键（比如 Ctrl+N 新建），如果需要，可以自行用脚本工具实现，或者让 Agent 帮忙加。

### 2. 搜索便笺

顶部搜索框直接打字即可，边打边过滤，不用按回车。搜索范围是**便笺标题 + 正文开头摘要**（不是全文检索），如果关键词埋在便笺很靠后的位置，可能搜不出来。

### 3. 置顶便笺（列表置顶）

在便笺卡片上点右键 → 选择"置顶"。

- 置顶的便笺会跳到列表最上方，卡片左侧出现橙色边线 + 📌 图标。
- 多条置顶时，默认按"最近置顶的排最上面"。
- 再次右键选择"取消置顶"即可恢复。

### 4. 给置顶的便笺手动排序

在置顶区域内直接按住便笺卡片拖动，松手即可调整顺序，拖动时有蓝色插入指示线提示落点。

几个边界规则：
- 拖拽排序只在置顶区域内部生效，不能跨区域拖到未置顶区域，反之亦然。
- 手动排过序后顺序固定保留，重启软件不会还原成按时间排。
- 搜索状态下拖拽排序会被自动禁用（列表被过滤、不完整时排序无意义）。

### 5. 删除便笺

删除入口是主列表卡片右上角的 × 按钮，点击后会弹出二次确认对话框，避免手滑误删。

> 注意区分：**主列表卡片右上角的 ×** 是真删除（有二次确认）；**便笺窗口本身右上角的 ×** 只是关闭窗口，数据完整保留，可随时从主列表重新打开，不会丢失任何内容。

## 四、便笺窗口：日常记录的主战场

### 1. 让便笺窗口悬浮在所有软件最上层

便笺窗口标题栏右侧有一个 📌 图钉图标按钮，点击后这个便笺窗口会悬浮固定在所有其他软件上方，切换到其他窗口时它依然可见，再点一次取消。

> 这里的"便笺窗口置顶"（悬浮在其他软件上方）和上面第三章的"列表置顶"（排在便笺列表最前面）是两个完全不同的功能，只是碰巧都叫"置顶"，注意区分。

### 2. 编辑便笺的标题

便笺窗口标题栏显示的标题，默认是正文第一行内容。点标题旁边的 ✏️ 铅笔图标可以单独编辑标题，Enter 确认，Escape 取消。

### 3. 关闭 vs 删除

窗口右上角的 × 只是关闭窗口，不删数据，关闭前会先自动保存一次。软件本身每隔 500 毫秒自动保存（带防抖），编辑过程中不需要手动按 Ctrl+S。

## 五、编辑器核心功能：任务与层级结构

编辑器的交互习惯参照飞书文档设计，用过飞书的话会比较熟悉。

### 1. 文字格式化

工具栏 B / I / U / S 分别对应加粗、斜体、下划线、删除线，前三个支持键盘快捷键：

- Ctrl + B → 加粗
- Ctrl + I → 斜体
- Ctrl + U → 下划线
- 删除线需点击工具栏 S 按钮（无快捷键）

### 2. 标题分级（H1 / H2 / H3）

工具栏支持设置 H1、H2、H3 三级标题，也支持 Markdown 语法（如 `#` 加空格）快速触发。

**H1 标题不只是"大字"，它还是划分"任务模块"的分界线**，可以通过拖拽 H1 标题来调整任务优先级（详见第 9 节）。习惯用法是：每个独立的大任务用一个 H1 起头，下面用列表展开细节。

### 3. 自动编号

编号是"活"的，根据"这是第几项"实时计算：

- 列表中间插入一行，后面编号自动顺延；删除中间一行，后面编号自动补上，永远保持连续正确。
- 遵循飞书的"中断延续"规则：有序列表中间夹了普通段落或无序列表，编号不会重置回 1，而是记住断点，后续接着数。

### 4. 输入"-"加空格，自动变黑点列表

空行行首敲 `-` 再按空格，自动变成黑色实心圆点的无序列表项，符号本身不会残留。同理，敲 `1.` 加空格可触发有序列表。

### 5. Tab 缩进：快速调整层级 + 编号自动继承

光标停在任意一行（不需要选中文字）：

- Tab → 这一行降一级，变成上一项的子项。
- Shift + Tab → 这一行升一级。

缩进层级变化后，相关编号会自动重新计算正确。典型场景：某一行本来想作为子任务，结果被识别成了跟父级平级的新标题，这时候光标停在那一行按 Tab，就能直接缩回去变成子项，编号自动接上。

### 6. Ctrl+A：先选中当前行，而不是全选

在乔巴便笺里，Ctrl+A 并不是直接全选，而是先选中当前行（跟飞书一致），这跟大部分软件的习惯不同，需要注意：

- 第一次按 Ctrl+A → 只选中当前行。
- 再按一次 Ctrl+A → 扩大为选中全文。
- 光标移动到别处后，这个进度会重置，下次按又从"只选当前行"重新开始。

这个功能主要是为了配合"任务状态标记"——标记进度时经常需要选中整行去改样式，有了这个不用再拿鼠标拖选。

### 7. 任务状态标记（🟢🟡✅）——核心功能

选中任意一段文字，气泡菜单会自动弹出（不需要按钮或快捷键触发）。菜单里有四个按钮：

- 🟢 进行中
- 🟡 待处理
- ✅ 已解决
- × 清除（取消标记）

切换逻辑：直接点新状态即可切换，不用先清除；如果点的是当前已经是的那个状态，则等于取消标记。

打上标记后，便笺就变成一幅清晰的进度地图：绿色代表正在推进，黄色代表排队等待，打钩代表已经搞定，扫一眼就知道每条任务线的状态。

### 8. 插入图片和链接

- **插入图片**：点工具栏 🖼️ 图片按钮，弹出系统文件选择框，选择图片后会转成 base64 内嵌到便笺里。目前不支持直接粘贴截图，只能通过选择文件的方式插入。
- **插入超链接**：工具栏插入链接按钮，插入后点击会用默认浏览器打开。

### 9. 任务模块化移动：调整优先级

H1 标题及其下所有内容（一直到下一个 H1 出现之前，不管中间嵌套多少层）在乔巴便笺里算作**同一个模块**。

鼠标悬停在 H1 标题上，左侧会浮现拖拽手柄图标。按住拖动时，模块会自动收起成只显示标题文字的"胶囊"跟随鼠标移动（避免长内容展开挡住视线），同时有蓝色插入指示线提示"松手会插到这里"。

松手后，模块连同其下全部内容一起挪到新位置，展开状态自动恢复。模块之间只能互相换位置，不能被拖进另一个模块内部，保持结构清晰。

这个功能主要用来应对优先级临时调整：本来排在后面的任务突然变紧急，直接抓住 H1 标题往上拖，整个任务连同底下的进度记录一起被提到最前面，不需要手动剪切、粘贴、重新调整层级。

## 六、快捷键速查表

| 快捷键 | 作用 |
|---|---|
| Ctrl + B | 加粗 |
| Ctrl + I | 斜体 |
| Ctrl + U | 下划线 |
| Tab | 当前行降一级（缩进） |
| Shift + Tab | 当前行升一级 |
| Ctrl + A（第一次） | 选中当前行 |
| Ctrl + A（第二次） | 选中全文 |
| Ctrl + Z | 撤销 |
| `-` + 空格 | 转无序列表（黑点） |
| `1.` + 空格 | 转有序列表 |
| Enter / Escape（编辑标题时） | 确认 / 取消 |

## 七、一些实用的使用习惯

1. **一个 H1 = 一条战线**：每个大任务用 H1 起头，下面用有序列表展开步骤，每步前用气泡菜单打上 🟢🟡✅。完成一个任务可以标记"已解决"后继续记录后续进度，或者缩进（回车 + Tab）记录这个任务的状态或其他内容。
2. **优先级用拖拽调**：哪个任务最要紧，就把对应的 H1 模块拖到最上面（或者在主列表把整条便笺置顶），确保眼睛先看到最重要的。
3. **做完的直接打钩 + 划掉**：一个子任务结束，Ctrl+A 选中那一行，点 ✅，一目了然。
4. **常驻悬浮**：指挥多个 Agent 时，把这条"总控便笺"用图钉悬浮在最上层，不管切到哪个窗口它都在，随手更新进度。

## 八、为什么会有这么个东西

这个工具最开始不是"设计"出来的，是"逼"出来的。

现在的工作方式，越来越多地变成"同时指挥好几个 AI 干活"——以前一个人干一件事，现在一个人当"包工头"，手底下好几个 Agent 各干各的。这种模式效率高，但对"记性"的要求变态——要同时记住五六条任务线，每条现在跑到哪一步、哪个卡住了、哪个等待验收。

市面上的待办软件要么太重（记进度非要建项目、拉看板），要么太轻（普通便笺连个像样的编号都做不好）。需要的东西其实很朴素：一个随手就能记、结构清晰、状态一眼可辨、还能永远飘在屏幕上的小本子。找不到，那就自己做一个。

整个开发过程几乎全程是拿需求跟 Claude Code 对话、让它去实现的——负责想清楚"到底要什么"，它负责把代码写出来。未来普通人的核心能力，可能不是自己会写代码，而是能把"我想要什么"这件事想清楚、说明白，工具交给 AI 去造就好了。
